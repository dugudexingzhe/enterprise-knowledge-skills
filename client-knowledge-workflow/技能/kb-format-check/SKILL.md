# 提交规范与格式预检

先读[通用规则与交接](references/通用规则与交接.md)和[提交规范与格式检查](references/提交规范与格式检查.md)。涉及平台时读[平台与核验来源](references/平台与核验来源.md)并核查当前环境；客户示例见[客户填写示例](references/客户填写示例.md)，记录见[工作册模板](references/项目工作册模板.md)。

## 收集前：给可执行规范

根据材料类型与用途给推荐格式和完整示例；优先复用已有文件，不要求先统一转PDF。说明证据原件、可编辑正文、结构化表格和独立图片如何关联。多工作表不自动不合格，嵌图不自动判图片丢失。

## 收到后：检查真实材料

读取项目说明与已有材料编号，列出文件范围并保留原件。可用Python 3.10+运行本地只读辅助：

```powershell
python -X utf8 "技能目录/scripts/preflight.py" --input "客户材料目录" --output "独立输出目录/格式预检.json"
```

辅助报告检查文件清单、签名、重复和部分Office结构；用相对路径映射项目既有M编号，不把扫描临时编号当永久编号。报告不包含正文内容，但文件名仍按客户资料管理。无需脚本时按同样规则人工查。

随后用当前环境可用的文档、PDF、表格、视觉工具打开文件；检查正文是否可读、扫描OCR是否正确、图片关键区域、表头/单位/脚注、全部工作表和图片对应关系。OCR需对照原件，关键数字/型号/日期重点复核。不能执行来源不明的文档宏、脚本或链接。

加密、损坏、缺工具或超限项目分别记原因；需要客户提供可读副本。工具没检查的项目列待检查，不能说不合格。自动风险信号需实际核对才升级为已证实的信息损失。

## 输出与通过条件

生成材料台账更新、逐文件结果、已证实问题与补件单、待人工检查项、平台试导入待办。说明是否只做本地技术预检，以及是否完成目标平台实际解析复核。扩展名被支持、脚本运行成功不等于材料可入库，更不等于内容真实。

格式通过的内容交给内容质检；读取失败或局部丢失只阻断受影响范围，不替客户改写未读取内容。
